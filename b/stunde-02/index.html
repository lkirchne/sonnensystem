Was bedeutet es, dass ArrayList eine Klasse ist?
a) ArrayList ist wie Planet oder Stern eine Klasse - mit Attributen und Methoden. Die Variable speichert eine Referenz (Adresse) auf das ArrayList-Objekt
b) ArrayList verweist immer auf ein Array
c) ArrayList kann nur andere Objekte referenzieren
d) ArrayList ist eine primitive Variable

Wichtig: Arrays und ArrayList - beides Objekte!

Array ist ein spezielles Objekt - fest in die Sprache Java eingebaut. Ein Array hat eine feste Größe und wird mit eckigen Klammern [] verwendet.

ArrayList ist eine Klasse aus der Java-Bibliothek - genau wie Planet oder Stern eine Klasse ist. ArrayList-Objekte haben Methoden wie .add() und .size().

Der Unterschied: Arrays haben eine feste Größe und spezielle Syntax ([], .length). ArrayList ist flexibel und kann wachsen - sie bietet viele nützliche Methoden (.add(), .remove(), .size()).

Beide sind keine primitiven Datentypen wie int oder double - beide sind Objekte!

Generics: Die spitzen Klammern

Was bedeutet <Himmelskoerper>?
▼

Was sind Generics?

Generics ermöglichen es, den Datentyp einer Klasse zu parametrisieren. Die Syntax sieht so aus:

ArrayList<Datentyp> name = new ArrayList<>();

Die spitzen Klammern <> geben an, welcher Typ in der ArrayList gespeichert werden darf.

Beispiele

// Eine ArrayList für Strings
ArrayList<String> namen = new ArrayList<>();
namen.add("Alice");  // ✓ Geht!
namen.add(42);       // ✗ Fehler! Nur Strings erlaubt!

// Eine ArrayList für Integers
ArrayList<Integer> zahlen = new ArrayList<>();
zahlen.add(42);      // ✓ Geht!
zahlen.add("Test");  // ✗ Fehler! Nur Integer erlaubt!

// Eine ArrayList für unsere Klasse
ArrayList<Himmelskoerper> objekte = new ArrayList<>();
objekte.add(new Planet());  // ✓ Geht!
objekte.add("Erde");        // ✗ Fehler! Nur Himmelskoerper!
Warum sind Generics nützlich?
a) Sie machen den Code langsamer aber sicherer
b) Sie bieten Typsicherheit und machen Code wiederverwendbar - der Compiler erkennt Typfehler schon beim Übersetzen
c) Sie sind nur syntaktischer Zucker ohne echten Nutzen
d) Sie ermöglichen mehrere Datentypen in einer Liste

Überlege

Was passiert, wenn du eine ArrayList ohne Generics deklarierst?

ArrayList objekte = new ArrayList();  // Kein <Typ>!
💡 Antwort

Ohne Generics kann die ArrayList alles speichern - Strings, Zahlen, Planeten durcheinander! Das ist unsicher, weil:

  • Du beim Auslesen nicht weißt, welchen Typ du bekommst
  • Du manuell umwandeln (casten) musst
  • Fehler erst beim Programmstart entdeckt werden, nicht beim Schreiben

Mit Generics prüft der Compiler schon beim Schreiben des Codes, ob die Typen passen!

Wichtig: Wrapper-Klassen für primitive Typen

Generics funktionieren NUR mit Objekten (Klassen), nicht mit primitiven Typen wie int oder double!

ArrayList<int> zahlen;     // ✗ Fehler! int ist primitiv
ArrayList<Integer> zahlen; // ✓ Richtig! Integer ist eine Klasse

Wrapper-Klassen sind "Verpackungen" für primitive Typen - sie machen aus dem primitiven Wert ein Objekt:

  • int → Integer (z.B. 42 wird zu einem Integer-Objekt)
  • double → Double
  • boolean → Boolean
  • char → Character

Autoboxing: Java konvertiert automatisch zwischen primitiven Typen und Wrapper-Klassen. Du kannst also einfach zahlen.add(42) schreiben, und Java macht daraus automatisch ein Integer-Objekt!

Was ist der Unterschied zwischen array.length und list.size()?
a) Kein Unterschied, beides gibt die Anzahl der Elemente
b) length ist ein Attribut (Klammern vergessen!), size() ist eine Methode (mit Klammern!)
c) length zählt ab 1, size() zählt ab 0
d) size() ist schneller als length

Aufgabe: Durchlaufen einer ArrayList

Es gibt mehrere Wege, durch eine ArrayList zu iterieren:

// Variante 1: for-Schleife mit Index (kennst du schon!)
for (int i = 0; i < objekte.size(); i++) {
    Himmelskoerper h = objekte.get(i);
    h.bewegung();
}

// Variante 2: for-each-Schleife (NEU und eleganter!)
for (Himmelskoerper h : objekte) {
    h.bewegung();
}

// Variante 3: while-Schleife
int i = 0;
while (i < objekte.size()) {
    objekte.get(i).bewegung();
    i++;
}

Welche Variante ist am besten für unser Sonnensystem?

🆕 Die for-each-Schleife verstehen

Die for-each-Schleife (auch "enhanced for loop") ist eine elegante Kurzform zum Durchlaufen von Collections wie ArrayList:

for (Datentyp variable : collection) {
    // Nutze die variable
}

So liest man das: "Für jedes Element vom Typ Himmelskoerper (nenne es h) in der Liste objekte, tue Folgendes..."

Beispiel zum Vergleich:

Klassische for-Schleife: 
for (int i = 0; i < objekte.size(); i++) {
    Himmelskoerper h = objekte.get(i);
    System.out.println(h.getFarbe());
}
 For-each-Schleife: 
for (Himmelskoerper h : objekte) {
    System.out.println(h.getFarbe());
}

Wichtig: Die Variable h ist automatisch das aktuelle Element - du musst nicht mit get(i) darauf zugreifen!

Was macht diese for-each-Schleife? for (Planet p : planeten) { p.setFarbe("rot"); }
a) Setzt die Farbe des ersten Planeten auf rot
b) Setzt die Farbe ALLER Planeten in der Liste auf rot
c) Gibt einen Fehler, weil p nicht definiert ist
d) Macht nichts, weil die Schleife leer ist

Wann for-each, wann klassische for-Schleife?

✅ Verwende for-each wenn:

  • Du alle Elemente durchlaufen willst
  • Du den Index nicht brauchst
  • Du nur lesend auf Elemente zugreifst oder ihre Methoden aufrufst

⚠️ Verwende klassische for-Schleife wenn:

  • Du den Index brauchst (z.B. für Position oder Nummerierung)
  • Du nur jedes 2. Element durchlaufen willst
  • Du Elemente während des Durchlaufens entfernen willst
💡 Beispiele 
// ✓ Gut für for-each: Alle Bewegungen aktualisieren
for (Himmelskoerper h : objekte) {
    h.bewegung();
}

// ✓ Besser klassische for: Index wird gebraucht
for (int i = 0; i < objekte.size(); i++) {
    System.out.println("Himmelskörper " + (i+1) + ": " + objekte.get(i).getFarbe());
}

Problem: Pegel-Zugriffe ersetzen

Was tun mit pegel-1 in urknall()?
▼

⚠️ Häufiges Problem bei der Migration

Viele von euch haben in der urknall()-Methode so gearbeitet:

this.addHimmelskoerper(new Planet());
this.getHimmelskoerper(this.pegel-1).setDurchmesser(10);
this.getHimmelskoerper(this.pegel-1).setX(50);
this.getHimmelskoerper(this.pegel-1).setFarbe("blau");

Problem: pegel gibt es bei ArrayList nicht mehr! Wie greifen wir auf das gerade hinzugefügte Element zu?

✅ Lösung 1: size() - 1 verwenden

Bei ArrayList nutzen wir objekte.size() - 1 für das letzte Element:

this.addHimmelskoerper(new Planet());
this.getHimmelskoerper(objekte.size()-1).setDurchmesser(10);
this.getHimmelskoerper(objekte.size()-1).setX(50);
this.getHimmelskoerper(objekte.size()-1).setFarbe("blau");

Warum size()-1? Wenn die Liste 3 Elemente hat, sind die Indizes 0, 1, 2. Das letzte Element ist also bei Index 2 = size()-1.

✅ Lösung 2: Lokale Variable (eleganter!)

Noch besser: Das neue Objekt in einer Variable speichern!

Planet erde = new Planet();
erde.setDurchmesser(10);
erde.setX(50);
erde.setFarbe("blau");
this.addHimmelskoerper(erde);

Vorteile:

  • ✅ Lesbarer und klarer
  • ✅ Kein mehrfacher Zugriff über Index nötig
  • ✅ Keine Fehler durch falsche Indizes
  • ✅ Funktioniert auch ohne ArrayList/Array-Zugriff

❌ Alt: Mit pegel

this.addHimmelskoerper(new Planet());
this.getHimmelskoerper(this.pegel-1).setDurchmesser(10);
this.getHimmelskoerper(this.pegel-1).setX(50);
this.getHimmelskoerper(this.pegel-1).setY(0);
this.getHimmelskoerper(this.pegel-1).setFarbe("blau");
this.getHimmelskoerper(this.pegel-1).setVx(0);
this.getHimmelskoerper(this.pegel-1).setVy(2);

✅ Neu: Mit lokaler Variable

Planet erde = new Planet();
erde.setDurchmesser(10);
erde.setX(50);
erde.setY(0);
erde.setFarbe("blau");
erde.setVx(0);
erde.setVy(2);
this.addHimmelskoerper(erde);

Vergleich der beiden Lösungen

Aspekt objekte.size()-1 Lokale Variable
Aufwand Minimal - nur pegel durch size()-1 ersetzen Mehr Umschreibarbeit
Lesbarkeit ~ Okay ✓ Sehr gut
Performance ~ Mehrfacher ArrayList-Zugriff ✓ Direkter Objekt-Zugriff
Fehleranfälligkeit ~ Index könnte falsch sein ✓ Kein Index nötig

Von manuell zu automatisch
▼

❌ Alt: Mit Array und Pegel

public void addHimmelskoerper(Himmelskoerper hk) {
    if (pegel < objekte.length) {
        objekte[pegel] = hk;
        pegel++;
    } else {
        System.out.println("Fehler: Das Array ist voll!");
    }
}

✅ Neu: Mit ArrayList

public void addHimmelskoerper(Himmelskoerper hk) {
    objekte.add(hk);

Wow! Was ist passiert?

Die Methode ist von 7 Zeilen auf 1 Zeile geschrumpft! Warum?

  • ✅ Keine Prüfung auf Platzmangel nötig - ArrayList wächst automatisch!

Was passiert, wenn die interne Kapazität der ArrayList voll ist?
a) Es gibt eine Exception
b) Die ArrayList erstellt automatisch ein größeres internes Array und kopiert die Daten
c) Alte Elemente werden überschrieben
d) Die add()-Methode gibt false zurück

    for (int i = 0; i < objekte.length; i++) {
        if (objekte[i] != null) {
            objekte[i].bewegung();
        }
    }
    zeichenflaeche.repaint();

Bonus: removeHimmelskoerper() vereinfachen

Falls implementiert: Jetzt wird's elegant!
▼

Falls du die Differenzierung gemacht hast...

Wenn du in der letzten Stunde die removeHimmelskoerper()-Methode implementiert hast, wird sie jetzt VIEL einfacher!

❌ Alt: Kompliziert mit Array

public void removeHimmelskoerper(int index) {
    if (index >= 0 && index < pegel) {
        // Alle Elemente verschieben
        for (int i = index; i < pegel - 1; i++) {
            objekte[i] = objekte[i + 1];
        }
        objekte[pegel - 1] = null;
        pegel--;
    } else {
        System.out.println("Fehler: Ungültiger Index!");
    }
}

✅ Neu: Einfach mit ArrayList

public void removeHimmelskoerper(int index) {
    if (index >= 0 && index < objekte.size()) {
        objekte.remove(index);
    } else {
        System.out.println("Fehler: Ungültiger Index!");
    }
}

Von 10 Zeilen auf 3 Zeilen!

Die remove()-Methode erledigt automatisch:

  • ✅ Element entfernen
  • ✅ Alle nachfolgenden Elemente verschieben
  • ✅ Größe anpassen

Weitere nützliche remove-Varianten

// Nach Index entfernen
objekte.remove(0);  // Erstes Element

// Nach Objekt entfernen
objekte.remove(meinPlanet);  // Entfernt das spezifische Objekt

// Letztes Element entfernen
if (!objekte.isEmpty()) {
    objekte.remove(objekte.size() - 1);
